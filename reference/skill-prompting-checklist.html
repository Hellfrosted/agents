Skill Prompting Checklist

A compact test for whether a durable Codex skill gives an agent enough direction without prescribing needless steps.

The minimum useful contract

OpenAI’s Prompting guide names goal, context, output, and boundaries. Repository adaptation: for agent skills, add the smallest verification that proves completion.

Outcome: What useful result should exist when the skill finishes?
Context: What paths, sources, state, or terminology can change that result?
Output: What form, audience, or evidence makes it ready to use?
Boundary: What must stay unchanged, never happen, or require approval?
Proof: What smallest check confirms the outcome?

Repository placement convention

This placement is a local design convention, not an official skill-file format. Use it only when it keeps a repeatable workflow clearer.

Repository convention: bound repeated work

For a genuinely repeated or persistent workflow, this repository uses a goal, an attempt budget, evidence per attempt, a stop condition, and a report of what was learned. Reuse the repository’s bounded-loop protocol instead of repeating it in every one-shot skill.

Repository default: avoid hard-coding model names

The current model guide recommends choosing a model and reasoning effort for the workload, then comparing representative tasks. Keep durable skills model-agnostic unless compatibility, evaluation, deployment, or a concrete workload constraint requires a pin.

Five-minute audit

  1. Can a reader say when this skill applies—and when it does not?
  2. Does the opening say what success looks like before it lists mechanics?
  3. Is every context item needed to change the result or protect a real boundary?
  4. Are detailed commands in a reference unless their exact sequence is safety-critical?
  5. Can the agent name the output and smallest proof before it starts?
